# Corpus — Coherence Diagnostic Bootstrap Training Data

This folder contains the full training corpus used to train the Coherence Diagnostic's Stage 1 DeBERTa classifier. It is released for reproducibility and inspection.

---

## Provenance

The corpus is a **bootstrap corpus**. The 4,186 design concept statements and their five-dimension binary labels were generated by Anthropic's Claude under the author's direction. Statement structure, dimension definitions, and annotation rationales were calibrated against interview transcripts from the author's design teaching practice. The author reviewed and guided generation; both the statements and their labels are Claude-produced.

**No statements were drawn directly from student work**, and no human rater other than the author was involved in calibration.

The deployed Coherence Diagnostic logs real student concept statements alongside classifier outputs as a foundation for eventual retraining. Usage is not yet at the volume that would justify a v2 retrain on logged data; when it is, the corpus and the model will be revised accordingly.

### Format

**Dict-format (`train.jsonl`, `val.jsonl`):**

```json
{"text": "concept statement...", "labels": {"CLAIM": 0, "EVIDENCE": 0, "SCOPE": 0, "ASSUMPTIONS": 1, "GAPS": 1}}
```

**With rationales (`train_with_rationales.jsonl`, `val_with_rationales.jsonl`):**

```json
{"text": "concept statement...", "labels": {"CLAIM": {"value": 0, "rationale": "..."}, ...}}
```

**Multi-label array format (`deberta_train.jsonl`, the format actually trained on):**

```json
{"text": "concept statement...", "labels": [0, 0, 0, 1, 1]}
```

Label order in the array: `[CLAIM, EVIDENCE, SCOPE, ASSUMPTIONS, GAPS]`.

### GAPS polarity

The GAPS dimension is **inverted**. For the four standard dimensions (CLAIM, EVIDENCE, SCOPE, ASSUMPTIONS), `1` marks the dimension as present / strong. For GAPS, `1` marks reasoning gaps as present (a problem). See `../annotation-schema.md` for full polarity specification.

## Validation methodology

The training script (`train_stage1.py`) consumes `deberta_train.jsonl` (4,186 statements) and applies its own random 90/10 train/eval split via `torch.utils.data.random_split`. The separately-prepared `val.jsonl` (723 statements) was created earlier in the data-preparation pipeline but **is not used by the training run**. Reported accuracies (see `../aggregate-performance.md`) come from the internal random 10% holdout (~419 statements) at the best checkpoint (epoch 4 of 5).

## Reproducing the training run

```bash
# Set up a python environment with transformers, torch, scikit-learn, sentencepiece
pip install transformers torch scikit-learn sentencepiece numpy

# Train (uses deberta_train.jsonl)
python train_stage1.py \
    --train_data deberta_train.jsonl \
    --output_dir outputs/deberta-coherence \
    --num_epochs 5 \
    --batch_size 8 \
    --learning_rate 2e-5
```

The training run produces a directory containing the fine-tuned model weights (~738 MB). The model used by the deployed tool is included in this repository at `../models/deberta-coherence/`.

## What this corpus is good for, and what it is not

**Good for:**
- Reproducing the Stage 1 classifier reported in the paper
- Inspecting the annotation criteria the model was trained on
- Building variants of the Coherence Diagnostic that follow the same architectural pattern
- Bootstrapping a similar tool for a different domain (replace the corpus, retrain)

**Not good for:**
- Validating the model against real student writing — that requires logged usage data, which is privacy-protected and not released here
- Drawing conclusions about how the model performs in live classroom use — accuracy on a held-out split of the same generation pipeline is not the same as accuracy on unseen real-world input
- Establishing pedagogical efficacy — that is a separate empirical question this corpus does not address
